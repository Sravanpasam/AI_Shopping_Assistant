Project Overview

Executive Overview: Project Goal & System Evolution

The Challenge & Core Goals
  • Real-World Problem: Traditional keyword search fails when shoppers use everyday conversational phrases ("something for dry frizzy hair") or inquire about store policies.
  • Bilingual Parity: Seamless native English and Arabic interaction with automatic right-to-left layout and cultural/currency translation.
  • Grounded Truth First: Zero hallucination tolerance: the bot never invents products, prices, or store policies.
  • Voice-First Access: OpenAI Whisper converts spoken voice directly into the search bar, enabling full digital inclusion.
Dual Architecture: System A vs System B
  • System A (Baseline - Frozen): Fast local retrieval pipeline combining sentence-transformer cosine intent classification, FAISS dense search, and regex policy parsing.
  • System B (Active LLM Agent): Autonomous tool-calling agent (Gemini 2.0 Flash / Groq LLaMA-3.3-70B) orchestrating 10 grounded tools in a bounded loop (≤5 rounds).
  • Navigation Over Walls of Text: Emits deep-link action objects that drive storefront UI pages (search, compare, orders) dynamically.
  • Offline Safety Fallback: Automatically falls back to local rules if cloud AI quotas are exhausted.
Dataset Selection

Dataset Selection & Structured Knowledge Repository

Non-Technical Rationale
  • Real Marketplace Benchmark: Sourced from Amazon Reviews 2023 (McAuley Lab) focusing on the All_Beauty category (~1,000 products, 9M+ reviews sampled).
  • Authentic Shopper Voices: Contains authentic customer reviews, star ratings, and real product specifications rather than synthetic dummy copy.
  • Realistic Store Policies: 5 comprehensive policy manuals covering returns (14-day window), warranty (12 mo electronics), shipping, payments, and cancellations.
  • Live Order Ledger: SQLite database (orders.db) modeling genuine customer fulfillment lifecycles (ORD-10001+).
Deep Technical Data Schema
  • Catalog Schema (catalog.parquet): parent_asin, title, store, price (USD), average_rating (1–5), rating_number, category_path, features_text, description_text, n_reviews_sampled.
  • Reviews Schema (reviews.parquet): parent_asin, rating, title, text, helpful_vote, verified_purchase, timestamp. Filtered to ≥5 verified reviews per item.
  • Policy Documents (docs/*.md): Segmented into semantic chunks by headers and paragraphs for dense vector retrieval.
  • Order Database (SQLite): Relational schema tracking order statuses, courier tracking IDs, and estimated arrival dates.
Pre-Processing Strategy

Pre-Processing Strategy & Query Normalization

Query Normalizer (query_normalizer.py)
  • Shopping Filler Removal: Automatically strips conversational filler in EN & AR ("I want", "show me", "أبحث عن", "من فضلك") while isolating search terms.
  • Catalog Typo Repair: Uses Gestalt pattern matching (difflib) strictly against words in the catalog (cutoff ≥ 0.72). Fixes "mascarra" -> "mascara" without corrupting brands.
  • Zero Neural Overhead: 100% deterministic rule-based processing executing in under 1ms on CPU.
  • Protected Tokens: Price tokens ('under', 'between', 'aed', '$') are protected from typo alteration so parsers read them accurately.
Price Parsing & Data Synthesis
  • Dual-Currency Parsing (price_parser.py): Extracts min/max price bounds from natural text ("under $20", "between 15 and 30 dollars", "under 100 AED").
  • Currency Parity: Converts AED amounts to USD using a fixed rate (3.67 AED = $1.00 USD) for seamless multilingual search.
  • False-Positive Shield: Distinguishes prices from volume/weight/counts ("50 ml", "pack of 2", "spf 30") to prevent bogus filters.
  • Catalog Text Fusion: Synthesizes title, category hierarchy, bullet points, and descriptions into unified semantic retrieval documents.
Model Selection

Model Selection & Configuration Topology

Local NLP Models (System A & Tooling)
  • Sentence-Transformers (all-MiniLM-L6-v2): 384-dimensional dense vectors, 22M parameters, ultra-fast CPU inference (~15ms), zero cloud API cost.
  • FAISS IndexFlatIP (Cosine Similarity): Normalized L2 inner product vectors for instant top-50 nearest neighbor retrieval.
  • Scikit-Learn TF-IDF Engines: Word N-grams (1–2) with sublinear TF scaling + Character N-grams (3–5) for typo resilience.
  • OpenAI Whisper (base / tiny): Multilingual ASR for speech-to-text. Browser audio (WebM) converted server-side to WAV via ffmpeg.
Agent LLMs & Translation (System B)
  • Google Gemini 2.0 Flash: Primary tool-calling agent. Fast time-to-first-token, native JSON schemas, temperature=0.2 for strict factual precision.
  • Groq LLaMA-3.3-70B Versatile: Hot-swappable OpenAI-compatible backup provider via httpx, activated automatically on quota limits.
  • Translation Pipeline (langdetect + deep-translator): Deterministic language tagging with sliding rate limiters (3 req/sec).
  • In-Memory LRU Cache: 2,000-entry memory cache eliminates repetitive API translation calls for recurring product titles.
Training / Adaptation

Training, Adaptation & Retrieval Engineering

Why Zero-Shot Retrieval Over Fine-Tuning?
  • The Flaw of LLM Fine-Tuning: Fine-tuning models on product catalogs leads to hallucinated prices, inventory drift, and high retraining expenses.
  • Retrieval-Augmented Generation (RAG): LLMs act as uncorrupted reasoning engines; live catalog, policy, and order data are injected via tools.
  • Zero-Shot Dense Similarity: Calibrated similarity thresholds empirically across positive queries and off-topic nonsense.
  • Fingerprinted Index Cache: FAISS index caches row counts and ASIN hashes, rebuilding automatically only when catalog files change.
Hybrid Reciprocal Rank Fusion (RRF)
  • RRF Formula: Score = 1.0 / (60 + DenseRank) + 0.35 / (60 + WordRank) + 0.15 / (60 + CharRank).
  • Dense + Lexical Balance: Dense vectors understand semantics ("tousled waves"); lexical vectors locate exact brand names and typos.
  • Search Acceptance Floor (0.51): Top hit must exceed 0.51 similarity to be accepted as a confident match.
  • Margin Pruning (0.16): Keeps only products within 0.16 of the top match, cleanly cutting off irrelevant tails.
Agent Architecture

Tool-Grounded Agent Loop & Navigation Actions

10 Grounded Agent Tools (agent_tools.py)
  • Catalog Tools: search_products (hybrid search + price bounds), get_product_details (specs), search_reviews (verified customer opinions).
  • Comparison Tool: compare_products builds deterministic spec tables directly from catalog attributes.
  • Policy & Knowledge: search_policies retrieves semantically matching chunks from policy documentation (floor 0.40).
  • Order Ledger: check_order queries SQLite orders.db for fulfillment status, tracking IDs, and estimated arrival dates.
  • Specialized Assist: build_routine, gift_finder, best_in_category, escalate_to_human.
Safety Boundaries & Navigation Actions
  • Strict Grounding Rules: Prompt explicitly forbids guessing. Every price, rating, date, and status must come from tool results in that turn.
  • Prompt Injection Defense: The prompt instructs the model to treat all tool outputs (reviews, descriptions) as untrusted data, never instructions.
  • No Fake Actions: The bot cannot claim to execute refunds or cancellations; it informs the user and initiates human handoff.
  • Structured Deep Links: Tool calls produce action objects (type: 'navigate', page: 'search' | 'compare' | 'orders' | 'help') to drive the UI.

Performance & Biases

Performance Analysis & Potential Biases

Multilingual & Dialectal Biases
  • Arabic Dialect Gap: Translation services assume Modern Standard Arabic (MSA); colloquial dialects (Egyptian, Gulf, Levantine) can experience translation drift.
  • Pre-Filtering Mitigation: Added Arabic character pattern matching and transliteration rules in query_normalizer and greetings.py before translation.
  • Whisper Dialect WER: Whisper 'base' model exhibits lower confidence on fast dialectal Arabic; resolved by supporting the 'small' model.
  • Bidirectional RTL Layout: Dynamic dir='rtl' styling ensures native Arabic visual alignment.
Catalog Skew & Review Sentiment Bias
  • Domain Concentration: Catalog is 100% beauty items. Dense vectors exhibit high baseline similarity for generic cosmetic words ('smooth', 'glow').
  • Lexical RRF Counter-Weight: Hybrid search balances semantic embeddings with word and character TF-IDF, preventing false matches on generic copy.
  • Review Positivity Skew: Sampled Amazon reviews skew heavily toward 4 and 5 stars. Pure text summaries can sound uniformly positive.
  • Quantitative Grounding: Surfaces raw average star ratings and total review counts directly alongside summaries to give an honest view.
Ethics & Society

Ethical, Legal & Societal Implications

Consumer Protection & Truth-in-Commerce
  • Preventing Financial Harm: An e-commerce bot that hallucinates a lower price or fake return policy creates legal liability and financial disputes.
  • Strict Grounding Constraint: Every factual claim (price, warranty period, delivery charge) is programmatically validated against retrieved tool output.
  • Clear Refusal of Unverifiable Facts: If information is not in the catalog or policy documents, the assistant explicitly states it is unavailable.
  • Medical Claim Defense: Questions asking for medical cures (e.g. 'will this cream cure my disease?') trigger safe refusal advising consultation with a doctor.
Authority Boundaries & Inclusion
  • Execution vs Reporting Boundary: Autonomous AI must not possess write-access to financial or refund databases. ShopBot is read-only and directs write requests to human agents.
  • PII Privacy Protection: Order tracking (/api/orders/<id>) sanitizes all personally identifiable information (customer name, address, card) and shows only fulfillment progress.
  • Accessibility Inclusion: OpenAI Whisper voice input empowers visually impaired, low-literacy, and non-native English speakers to shop seamlessly.
  • Human Escalation Protocol: Recognizes customer frustration and billing disputes, instantly providing seamless handoff to human support.
Resilience & Reliability

Production Resilience & Fallback Safety Net

Multi-Tier LLM Fallbacks & Budgeting
  • Automatic Model Rotation: If the primary model (Gemini 2.0 Flash) encounters a 404 (retired model) or quota exhaustion (429), it automatically rotates to backup models.
  • Groq Secondary Provider: Full cross-provider redundancy via Groq (LLaMA-3.3-70B). Switching providers requires only changing LLM_PROVIDER in .env.
  • Daily Quota Protection: LLM_DAILY_BUDGET enforces a per-model ceiling (default 20 calls/day), preventing cloud API overages.
  • Thread-Safe Rate Limiting: Outgoing client calls are paced by a shared sliding-window rate limiter (10 req/min).
Offline Fallback Net (fallback.py)
  • Zero-Downtime Guarantee: When all LLM models are exhausted or network is unavailable, the system switches to fallback.py.
  • Local Rule-Based Execution: Executes local FAISS search, policy extraction, and order checks using fixed templates without calling external APIs.
  • Graceful Status Surfacing: GET /api/health surfaces 'quota_exhausted', updating the widget status indicator to amber without crashing.
  • Eval Cache (LLM_CACHE): Stores SHA-256 hashed chat responses in data/llm_cache.json, allowing benchmark reruns without consuming LLM API calls.
